# 工作流合成资料契约

`data/workflow/` 下的资料由 `scripts/generate_workflow_materials.py` 确定性生成，
全部为虚构记录。应用启动时由 `materials.py` 导入 SQLite；字段名、类型和关联关系
即本文件描述的内容。

## 参考资料

### `reference/staff.csv`（16 行）

| 字段 | 含义 |
| --- | --- |
| `user_id` | 人员编号 |
| `display_name` | 显示名（虚构） |
| `role` | `store_manager` / `analyst` / `data_governor` / `business_owner` |
| `department` | 所属部门：`store-ops` / `merchandising` / `finance` / `data` |
| `region_scope` | 可工作的地区：`R-N` / `R-S` / `R-W` / `ALL` |
| `personal_clearance` | 是否具备个人数据许可（0/1） |
| `active` | 是否在用（0/1） |

### `reference/stores.csv`（12 行）

门店编号、名称、地区、店型、开业日期和在用状态。三个地区各有 4 家在营门店。

### `reference/datasets.csv`（3 行）

| 数据集 | 敏感级别 | 个人数据 | 说明 |
| --- | --- | --- | --- |
| `DS-STORE-DAILY` | `internal` | 0 | 门店日汇总，经营诊断和计划可用 |
| `DS-MEMBER-DAILY` | `personal` | 1 | 会员脱敏明细，仅会员跟进场景 |
| `DS-FINANCE-LEDGER` | `restricted` | 0 | 财务总账摘录，本应用未接入事实表 |

### `reference/metric_catalog.csv`（10 行）

| 字段 | 含义 |
| --- | --- |
| `metric_id` | 指标版本编号 |
| `metric_name` | 指标名，可重复（不同部门口径不同） |
| `definition_version` | 口径版本，如 `DEF-1` |
| `grain` | 计算粒度 |
| `owner` | 口径负责部门 |
| `audience_departments` | 允许使用该口径的部门，分号分隔 |
| `status` | `active` / `review` / `retired`；只有 active 可交付 |
| `valid_from` / `valid_to` | 口径有效期 |
| `calculation_key` | 计算实现键；同一指标名的不同版本对应不同算法 |
| `source_dataset_id` | 所需数据集 |
| `definition_text` | 中文口径说明 |
| `personal_data` | 是否涉及个人数据（0/1） |

示例：`net-sales` 的 `DEF-1`（财务：毛额减退货）只适用于 finance 和 store-ops；
`DEF-2`（商品部：毛额）只适用于 merchandising；两者数值不同。

### `reference/access_policies.csv`（11 行）

| 字段 | 含义 |
| --- | --- |
| `policy_id` | 策略编号 |
| `dataset_id` | 数据集 |
| `region` / `role` / `department` / `purpose` | 匹配维度，`*` 表示任意 |
| `min_clearance` | 所需个人数据许可 |
| `decision` | `allow` / `limit` / `deny`，治理决定不得宽于此 |
| `policy_version` | 策略版本 |
| `valid_from` / `valid_to` | 有效期 |
| `note` | 中文说明，会写入访问决定快照 |

### `reference/business_events.csv`（6 行）

地区、事件类型、起止日期和说明。分析结论会附上与请求期间重叠的经营事件，
只作为解释线索，不作因果断言。

### `reference/data_versions.csv`（3 行）

| 版本 | 序号 | 覆盖截止 | 状态 | 说明 |
| --- | ---: | --- | --- | --- |
| `DV-2026-11-10` | 1 | 2026-11-09 | published | 常规周批 |
| `DV-2026-11-17` | 2 | 2026-11-16 | published | 北区两家门店 11-10 至 11-16 数据迟到 |
| `DV-2026-11-24` | 3 | 2026-11-23 | ready | 补齐迟到数据并新增 11-17 至 11-23 |

只有 `published` 版本能用于交付。`ready` 版本需治理人员 `publish-version` 后才能选用。

## 事实资料

### `facts/store_daily.csv`（1,380 行）

12 家门店 × 115 天（2026-08-01 至 2026-11-23）。

| 字段 | 含义 |
| --- | --- |
| `date` | 营业日 |
| `store_id` / `region` | 门店与地区 |
| `visits` | 到店人次（含员工代客下单） |
| `transactions` | 成交笔数（含员工代客下单） |
| `group_visits` / `group_transactions` | 顾客口径的到店与成交（剔除员工代客） |
| `staff_transactions` | 员工代客下单笔数 |
| `gross_sales` | 商品成交毛额 |
| `group_gross_sales` | 顾客口径毛额 |
| `return_amount` / `return_count` | 退货金额与笔数 |
| `stockout_skus` / `total_skus` | 缺货与在售 SKU 数 |
| `available_seq` | 该行进入数据版本的批次序号 |

### `facts/member_daily.csv`（4,420 行）

| 字段 | 含义 |
| --- | --- |
| `member_ref` | 脱敏会员标识，非真实个人 |
| `date` / `store_id` / `region` | 归属 |
| `transactions` / `spend` | 当日笔数与金额 |
| `available_seq` | 批次序号 |

会员明细只允许用于 `member-followup` 场景，且应用只输出门店聚合；统计窗口内
会员记录少于 10 条的门店值会被抑制。

## 缺失与状态语义

- 数据缺失、迟到、超出覆盖或未回执都表示“未知/处理中”，**不能解释为零值或成功**。
- `available_seq` 大于所选数据版本的批次不参与计算。
- 同日同店在某一版本中完全缺失时，覆盖报告列出区间和门店，不会静默补零。
- 合成日期用于复现跨期与迟到关系，不对应真实业务发生。

## 与早期基线资料的关系

仓库根目录 `data/` 下的 `requests.csv`、`metric_catalog.csv` 等是早期样例，
字段更少、存在跨文件不一致，仅由 `tests/test_materials.py` 做格式校验。
本应用使用 `data/workflow/`，两者互不影响。
